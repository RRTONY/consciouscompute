# Ambiguous Corrections

> When a terse correction could undo a recent explicit decision, ask which change before editing

Conscious Compute rule: if the user has just approved a change and then sends a short, rough correction, it may mean "undo that change" or something narrower (for example "don't touch that other page"). Ask a concrete question that lists the exact earlier change instead of guessing.

**Why:** Guessing wrong either way (reverting wanted work, or keeping unwanted work) costs real edits and trust.

**How to apply:** When a short correction could contradict a recent explicit decision, don't infer intent from grammar. Ask an options-based question that names the specific prior change before editing or reverting.
